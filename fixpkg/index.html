fix
A simple, source-based and declarative package manager.

Build your environment from source.

fix is a lightweight package manager designed for building packages directly from source and creating reproducible development environments. Inspired by Nix, fix keeps the same declarative idea while using a simpler and more approachable design.

View Source

Build from Source

Build packages directly from their source code instead of relying on pre-built system packages.

Declarative

Define the packages and dependencies required by an environment using a simple declarative specification.

Reproducible

Keep the environment definition in a file so it can be recreated consistently across systems.

Isolated Shells

fix creates a new shell containing the packages defined by the current environment.

State Tracking

Environment state is recorded in a file, making configurations easy to inspect, version and share.

Nix Inspired

fix takes inspiration from Nix while focusing on a smaller, simpler and easier-to-understand workflow.

Simple by Design

Traditional package managers usually install packages directly into the system environment. fix takes a different approach. A project describes what it needs, and fix creates an environment based on that description.

The goal is not to reproduce every feature of Nix. Instead, fix focuses on the core ideas of declarative environments, source-based builds and reproducibility while keeping the implementation and user experience simple.

Declarative Environments

A fix environment describes the software required by a project. Instead of manually installing every dependency, the environment can be defined once and recreated when needed.

packages: - gcc - make - git - curl shell: development

Enter the Environment

Once the environment is defined, fix builds the required packages and starts a new shell with the requested software available.

$ fix shell Building dependencies... Building gcc... Building make... Building git... Starting development shell... $ gcc --version $ git --version

Why fix?

Less Complexity

A smaller conceptual model makes fix easier to understand, configure and maintain.

Source First

Packages are built from source, giving developers more control over how software is produced.

Project Focused

Environments can be defined per project instead of modifying the global system environment.

Version Control Friendly

Environment definitions can live alongside project source code and be tracked with Git.

A Lightweight Alternative

fix is designed for developers who want the benefits of declarative and reproducible environments without adopting the full complexity of a large package management system.

$ fix init Creating environment... $ fix install gcc Building gcc from source... $ fix shell Entering fix environment...
